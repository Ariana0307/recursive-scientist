# 最终测试协议 — G4 r1

本协议随G4标准提交冻结。G4没有训练或测试评分授权；正式搜索尚未开始，最终阶段状态WAITING。

1. 调参、随机搜索、AI反馈、确认与早停只用固定train/validation，不对官方test进行解码评分、不把test成绩或标签放进Agent上下文。归档完整性校验读压缩字节不等同于test评分，但不能靠布尔记录声称实现了OS隔离。
2. 在任何test评分前锁定baseline、Random最佳、AI最佳的选取与确认规则。搜索最佳按validation accuracy最大；并列按validation loss最小；仍并列按config hash字典序。失败项不伪造成功分数，策略无成功候选则报告缺席。规则不因test结果改变。
3. 确认使用新seed1001/1002/1003，同一候选确认配置、epochs、设备安排和每策略预算必须事先一致并另行授权；当前没有确认授权。事前锁定如何聚合确认值、如何处理失败、以及哪个确切模型工件进入最终名单。不得看test后挑seed/权重。未锁定这些规则即WAITING，不执行确认或最终评分。
4. 冻结最终清单，通常三类各一个预选模型；若数量不同必须事先明确。每项绑定策略/实验ID、config/seed/hash、训练与split hash、runner commit、模型结构和权重SHA256。还需锁定测试数据版本/hash、评分源码commit与SHA256、预处理、指标单位、评估清单与阶段ID、批准记录。只有配置没有权重不能算完成封存。
5. 全部工件封存后统一执行一次最终测试阶段，每个预选模型只评分一次。使用完整官方test、固定评分与预处理，不训练/不更新参数。相同权重工件出现多个别名时去重计算一次，不能当独立重复。
6. 一次性评分要有事前预留、模型hash与阶段ID绑定及不可覆盖的终态证据。完整历史结果只能验证后重发，不能重新算。崩溃/缺失/歧义状态记录failed/unknown，禁止自动重新评分以取得更好结果；再次评估需新协议与批准，不能仍声称本阶段每模型仅一次。
7. 最终结果统一封存/报告，不反馈任何调参、确认、模型替换或停止规则。看过test后若改变方案，应停止原轮推断，登记协议偏离，不能继续把此test视为未见的验证依据。

当前已知缺口：被审查G3 runner只保存请求/结果/validation预测/环境和统计，没有保存模型权重，也没有最终test执行器或一次性测试账本。因此不能对原G3模型直接复评test。未来必须在任何test访问前，按统一批准流程保存训练工件，或明确另行授权的固定重建训练并锁定新工件；不得把新工件冒称原权重。本轮不重训、不建测试入口、不填写test accuracy/loss。

信任边界保持为无shell/文件工具的科研模型与可信操作者；评分版本、规则和结果不交由模型改写。这不是同UID任意程序的OS不可篡改保证。后续实施须给出实际接口权限和审计证据，不能只凭文档判PASS。
