# G3 最终测试阶段规范提案

状态：PROPOSAL / WAITING；当前 runner 没有最终测试模式或模型权重导出，本轮不训练、不加载官方 test、不报告任何测试成绩。

## 阶段边界

1. 调参只用固定 45000 train / 5000 validation；官方 test 不解码、不评分、不用于提示、选择、早停或失败恢复。归档完整性 hash 会读取压缩归档字节，不等于加载 test 样本评分；仍需在未来执行环境验证访问控制，而非仅信任布尔日志。
2. 查看 test 之前，冻结 baseline、随机最佳、AI 最佳的选择规则与确认规则。建议选择规则先按 validation accuracy 最大、并列按 validation loss 最小、仍并列按 config hash 字典序；失败配置不伪装低分成功，候选全部失败则该策略缺席并如实报告。规则一经批准不得因 test 结果改动。
3. 提前锁定确认是否执行、确认 seeds/次数/epochs、每策略相同预算、聚合与并列规则、失败/重试记账；无确认则明确写 none。确认只能使用 train/validation，且在最终封存名单前完成。没有新授权不得运行确认。
4. 锁定最终清单（建议三类各一件模型，完整数量必须事先明确）。每项绑定策略、原始实验 ID、config/seed/hash、训练数据和 split hash、runner commit、环境、模型结构及权重 SHA256；同时锁定测试集版本/hash、评分代码 commit/hash、预处理、指标单位、一次性执行计划、审阅批准者与封存时间。不能只锁“最佳配置”后在看到 test 后换训练 seed 或权重。
5. 全部模型封存后统一执行一次最终测试阶段；每个预选模型只评分一次。完整官方 10000 test 样本，统一固定预处理与指标；不训练、不更新参数、关闭训练态。物理上相同的模型工件若被多个策略选中，提前明确只计算一次、报告别名，不能把重复评分当重复证据。
6. 所有最终结果同时封存并报告；不得反馈给 Agent、随机搜索、超参选择、确认、早停或重新选择。看到 test 后需要调整则结束本协议，登记偏离；不能再把同一个 test 当作未见的确认集。

## 单次评分如何可审计（尚未实现）

由与调参 Agent 分开的评估身份执行可信只读评分代码和封存模型；调参角色不应具备测试标签、评分文件或原始结果的写权限。以模型权重 hash+冻结阶段 ID 为幂等键，原子预留后记录 attempted/running/terminal，保存全部原始计时/失败；不靠换 ID 重新评分。当前不存在这样的已验证隔离或一次性测试账本。
预检只查权重、代码、清单格式/hash 和资源可用性，不暴露 test 成绩；评分阶段若崩溃、结果缺失或状态不明，记录 failed/unknown，禁止自动重评同一模型以取得更好结果。完整已封存的原结果可验证后重发，不重新计算。任何无法完成的最终阶段要声明不完整；再执行需要新协议与明确批准，不能宣称仍是本次“一次评分”。
