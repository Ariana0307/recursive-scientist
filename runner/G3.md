# Trusted G3 campaign (three starts only)

This is the user's explicit G3 authorization, not a reset or alternate path around
G1. `g3-method.json` freezes policy/statistics before execution. Authorize and run
only a clean committed checkout with the existing independent Python 3.12 venv.

The trusted operator has these fixed commands (no path/campaign/command flags):

- `python -I -B runner/campaign_cli.py authorize`: exclusively create this one
  campaign's authorization. This command is **not** a scientific-agent tool.
- `python -I -B runner/campaign_cli.py run`: read one closed `Config` JSON from
  stdin. Only the authorized baseline values and the next seed 42,43,44 pass.
- `python -I -B runner/campaign_cli.py summary`: deterministic audited summary.

No scientific model runs on this worker or has a shell/filesystem tool here. The
only model-facing interface is Config JSON submitted to the trusted operator's
launcher. It cannot set campaign, paths, quota, IDs, commands, or approve itself.
The operator creates signed authorization, mirrored append-only reservations,
and a private signing key (never exported). Store/authority are owner-only; the
scientific-agent tool surface must not expose them or the authorization command.
**Same-UID unrestricted shell is outside this boundary:** chmod/HMAC cannot defend
against an operator-equivalent process that can read its key or change code. Do
not grant such access to research agents; a future hosted agent needs a genuinely
separate OS/service identity or no-host-access structured broker. Nothing here
changes accounts, SSH, firewall, or opens a server.

Campaign identity/three-start/300s policy is versioned; runtime authorization also
binds the actual clean full commit, method hash and evaluator hash. Parent checks
all bindings, reserves before spawn, and passes only a sealed memfd capability.
The real training child independently verifies policy/signature/slot/request/
parent and atomically claims a one-use marker before importing torch. Concurrent
admission holds an authority lock; starts must finish serially in fixed seed order.
Missing ledger mirrors/orphans fail closed. Failures, cancellation and spawn
failure retain consumed reservations. No retry or replacement after failure is
authorized in this three-seed campaign. G1 storage/CLI remain compatible and its
old two-slot ledger remains unchanged.

New private state is under the fixed project-private `campaigns/` and
`campaign-authority/` directories, not an arbitrary model-selected directory.
A crash between primary and mirror commits deliberately blocks further starts;
manual review may reconcile evidence, never refund a launch or reset a ledger.
Timeout supervises only its own new process group, including import/data/model
initialization and scoring, and preserves non-success with null metrics.

`evaluate.py` is a mechanical extraction of the G1 scoring loop, with optional
small `(training_index, target, predicted_class)` evidence. Structural AST and CPU
numeric equivalence tests cover the extraction; its SHA256 is pinned in the
method and checked by both parent and child. Model, preprocessing, split and score
formula remain unchanged. Prediction evidence only uses the 5000 validation
indices; official test data is never scored. Training imports this fixed module;
model input cannot choose/import/modify scoring code.

Statistics use ONLY the three successful G3 accuracies: arithmetic mean,
sample standard deviation ddof=1, and 2*sigma as an exploratory noise threshold,
not a significance proof. Any missing/failed seed means the complete-three mean
and sigma are null; individual real results remain. Best-so-far is computed from
validated matching Results by deterministic code and appends only on strict
accuracy improvement; ties/worse never overwrite it. No weights are produced.
